# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root for shared domain terminology.
- `docs/adr/` for architecture decision records.

## Before exploring

Read the root glossary and ADRs relevant to the area being explored.
If either is absent, proceed silently. The domain-modeling skill creates these
documents when terminology or decisions are resolved.

Use [README.md](../../README.md), [Native publishing](../NATIVE_PUBLISHING.md), and [Notion publishing](../NOTION_PUBLISHING.md) for existing contracts.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and test names.
If a needed term is missing, check existing usage and note genuine gaps for
domain-modeling.

## Decisions

Surface conflicts with an existing ADR explicitly, identifying the decision
and explaining why it may need reconsideration.
